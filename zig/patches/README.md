# zig/patches

Patches to BertholomusAI's TensorFold fork at `TF_REF` (`scripts/config.sh`), applied in filename order by `zig/Dockerfile`
(`git apply` in the checkout's root). The image tag changes with them. `zig/patches-inputs/` holds the patches for the
second checkout (branch `deepseek-v41-zig-tp4` at `INPUTS_REF`) that builds `tf-dsv41-rank-cache`; the Dockerfile applies
them there the same way.

| Patch | Switch (both ranks) | Default | What it does |
| --- | --- | --- | --- |
| `0001-c7-indexer-split.patch` | `TF_DS_IDX_SPLIT` (unset: threshold; `1`: always; other: off) | **on from token 131,072** | splits the prefill indexer's row blocks between the two ranks and all-gathers the selections, in chunks that end at 65,536 compressed keys or more; below that the replicated loop runs (idea: drowzeys, GLM-5.3-Flash recipe) |
| `0002-c3-engram-lanes.patch` | `TF_DS_ENGRAM_LANES=2` | off | a second AIO ring for a prompt chunk's Engram reads |
| `0004-call-gate.patch` | none (always on) | **on** | enforces `tool_choice` `"required"` and a named function: the answer opens with the first token of the template's tool-call markup (for this model, the `<` before `｜DSML｜`) and finishes an offered tool name; requests without `tool_choice` are unchanged (taken from the spark1/spark2 deployment's copy of this recipe; tested: required and named choices return tool calls, auto/none/absent unchanged) |
| `0005-prefill-interleave.patch` | `TF_DS_PREFILL_INTERLEAVE_MS=N` (rank 0 only; recipe setting `PREFILL_INTERLEAVE_MS`) | off | between two chunks of a long prompt pass, rank 0 runs the other live streams' decode rounds for up to N ms and takes their cancels, so a cold long prompt slows a chat instead of freezing it (issue #3). **By Coinupbtc**, [pull request #5](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/5), tested there for bit-identity (long prompt and chat replies equal the unpatched solo ones, with and without drafts) |
| `0006-image-prompt-cache.patch` | `TF_DS_IMAGE_CACHE=0` turns it off (server; rank 0) | **on** | a prompt with pictures resumes and keeps prompt states, keyed by the pictures' content; a request with pictures and no key never touches the cache (issue #2) |
| `0008-pool-window.patch` | `TF_DS_POOL=N`, `TF_DS_WINDOW=W` (both ranks; recipe setting `POOL`, which sets both and `--pool` on rank 1) | off | the shared pool may be larger than the window (`--context`): the streams' extents and kept prompts share N positions while a request still stops at W; the RoPE tables are sized by W (a stream's positions run from 0 inside its extent), not by the pool. Applies on its own and in either order with a patch that adds `display.zig` |
| `0010-rdma-idle-nap.patch` | `TF_RDMA_IDLE_S` (default 2 s; 0 keeps the always-spinning proxy), `TF_RDMA_NAP_US` (recipe default 500; the patch's engine fallback is 100) | **on** | the RDMA gather's proxy naps once the engine is idle instead of spinning a core on each rank (the logic of [TensorFold PR #27](https://github.com/bertholomus/TensorFold/pull/27), ported to the Zig ring). A decode round's gathers come microseconds apart, so they never see a nap; the first gather after a quiet spell waits at most one nap (~0.5 ms at 500 µs) |
| `0011-cuda-budget-parked-pages.patch` | none (always on) | **on** | the startup budget counts the free pages parked on the kernel's per-CPU lists, so the first start after an image load is not budgeted GiBs short (GLM `0119`, PR #149); sizing only |
| `0012-dsv41-base-fixes.patch` | none (always on) | **on** | a prompt pass drops the Engram read-ahead an interrupted earlier pass left (a resume at that chunk took rows of the other prompt); `0010`'s timer-slack `prctl` runs on Linux only (the host tests build on macOS) |
| `0013-core-spill-store.patch` | none (a library) | off | core/spill: spill v2's disk block store (2048-token blocks that turns and forks share, lineage, durable writes, recovery, room by conversation); nothing calls it before 0014 and 0016 (GLM `0088`/`0110`, PRs #78 and #124; BadAd84's block-tier design, #118) |
| `0014-core-cache-tier.patch` | the spill flags of 0016 | off | the prompt cache's spill Tier and restore jobs beside decoding, and continued chats (`0111`, PR #128) |
| `0015-dsv41-kv-shard-attn.patch` | `KV_SHARD` (`TF_DS_KV_SHARD=1`), `KV_SHARD_DECODE`; the pool is `0008`'s `POOL` | off | KV sharding, first half (`0118`, PR #152): each conversation's compressed latents stored once, on the Spark whose part of `0008`'s pool holds them, every part a whole window; byte-exact fetches; the part planner 0018 uses (one stream until 0018) |
| `0016-dsv41-spill-blocks.patch` | `SPILL_GIB` (`--spill-gib`; `TF_DS_SPILL_*` and the identity on both ranks) | off | spill v2 on the pair (`0110` on `0088`): kept states written to each Spark's disk when kept and read back beside decoding, also after a restart; the rank protocol and the fingerprint the ranks agree on |
| `0017-dsv41-kit-row-split.patch` | none (the opt-in kernel: build option `-Dport_kernels`, off) | **on** above 16 round rows | `ROUND_ROWS=32` on the pinned kit (a MoE gate the kit cannot launch whole runs as 16-row parts), the kit's variant tooling, spill's opt-in plane staging kernel |
| `0018-dsv41-kv-shard-lanes.patch` | `KV_SHARD_CARRY`, `KV_SHARD_TWINS`, `KV_SHARD_CHECK` (with `KV_SHARD=1`) | on with `KV_SHARD` | KV sharding, second half (`0118`): the planner in the lanes, so `--parallel` streams shard; part-local placement, carries, borrowed rows for prompts, the ranks' digest checks |
| `0019-dsv41-spill-kv-shard.patch` | `SPILL_GIB` together with `KV_SHARD=1` | off | spill v2 with KV sharding (owner-sharded stores, a restore lands in the part it was kept from), rank protocol v2, a follower's store opened on its own thread |
| `0020-dsv41-pair-broken.patch` | `TF_DS_PAIR_BROKEN` (`exit`; `degrade` opts out, any other value refuses the start), `TF_SPILL_DEFER_MS` | **`exit` with two ranks** (one rank: nothing changes) | a broken rank pair ends the server with status 75 instead of hanging it, for a supervisor to restart both ranks (`docs/systemd.md`): a dead follower's link breaks it at once, NCCL and RDMA-ring aborts, a stall monitor for a hung one (120 s without progress while busy) and a 15 s drain deadline after a break, both fixed; the pair's state on `/health` (503 `stalled` / `broken`) and `/metrics`; acts only after a failure, so replies are unchanged; a restore refused for capacity waits instead of prefilling |
| `0021-dsv41-spill-pictures.patch` | `TF_DS_IMAGE_CACHE=0` turns it off (with 0006) | on with `SPILL_GIB` | spill v2 for prompts with pictures: a point records each picture's span and full SHA-256 (manifest version 3); every rank counts its own |
| `0022-dsv41-kv-shard-ring.patch` | `TF_DS_KV_SHARD_RING`, `KV_SHARD_DECODE=auto`, `TF_DS_KV_SHARD_COST`, `TF_DS_KV_SHARD_OVERLAP` (with `KV_SHARD=1`) | on with `KV_SHARD` | the sharded decode's exchanges on the RDMA ring, sized to the rows that cross (decode ~1-4 % below unsharded; 10-12 % on NCCL before) |
| `0023-server-prepare-memory.patch` | `TENSORFOLD_PREPARE_FLOOR_GIB` (rank 0; GiB, `0` turns the gate off) | **on** (3 GiB) | not the port's: a fix to the base engine. A long prompt's render and tokenization give their scratch back, and a prepare waits under a memory floor while others are in flight: eight resumed ~1M-token conversations no longer take rank 0's MemAvailable to zero. Also offered alone as its own pull request; whichever lands first, the other copy goes |
| `0024-mixed-pack.patch` | none (the rank cache's plain entries decide; both ranks) | **on for mixed packs** | EAQ v1.1's 27 BF16 indexer/compressor linears (8 `attn.wq_a`, 8 `attn.indexer.wq_b`, 4 `attn.compressor.wkv`, 3 `attn.compressor.wgate`, 4 `attn.indexer.wk`) load as plain BF16 dense linears through cuBLAS (`cublas.Blas.linearBf16`, torch's bf16 `nn.Linear`) in decode and prefill, instead of EXL3 trellis parts. A rank cache from an EXL3-only pack has no plain entries and the engine runs exactly as before; a mixed pack's rank cache plans them with `zig/patches-inputs/0001-mixed-pack-rank-cache.patch`. The load prints `mixed pack: 27 float linears` |
| `0025-widen-bf16.patch` | none (always on) | **on when the source is BF16 where the plan wants f32** | the checkpoint reader widens a BF16 source to f32 exactly (BF16's bits in the high half, zeros below), as the loader's `.to(torch.float32)` does. EAQ v1.1's 8 `attn.indexer.weights_proj.weight` are BF16 in the pack while both loaders plan them as f32 (v1 stores them so too); without the widen the rank-cache writer stopped with `error: UnsupportedConversion`. `zig/patches-inputs/0002-widen-bf16.patch` does the same in `tf-dsv41-rank-cache`, which writes the weight file |
| `0026-plain-rows.patch` | `TF_DS_PLAIN_ROWS=N` (both ranks; default 16; `0`: the round's own rows) | **on** | a mixed pack's plain (cuBLAS) linear runs over at least N rows, never beyond a round's rows (the buffers are sized for those). cuBLAS picks its kernel and split-K from the GEMM's shape and its rounding follows the pick, so a decode round's row count changing with the streams or the draft block could change a token's bits; a fixed shape keeps them the same. Without it, on the pair, drafts-on and drafts-off replies matched 4 of 8 `tools/validate.py` prompts, and its 8-concurrent check matched 4 of 8 with drafts off (6 of 8 with drafts on). The EXL3 linears are untouched: their kernels compute each row in a fixed order |
| `0027-tool-call-prose.patch` | none (always on) | **on** | the text a DeepSeek-V4.1 reply writes before its tool calls is the reply's content, without the two newlines that start the calls, as the checkpoint's reference parser reads it (`encoding.py`: the calls start at `\n\n<｜DSML｜ calls`). Before, a reply without streaming returned `"content": null` whenever it made calls (the client never saw the text, and sent the turn back without it), and a streamed reply sent the newlines as content (a client that keeps the content as it arrived sends back `text\n\n\n\n<｜DSML｜ calls>`, and the next prompt stops matching the generated tokens there). Replies keep their bits: only the response's content field changes. **By Coinupbtc** |
| `0028-plain-request-text.patch` | none (always on) | **on** | a request's own text never becomes a control token (issue #21): before the template renders, every string of the messages and tools gets the tokenizer's plain mark (U+FDD0, a noncharacter) after the first character of each added token written in it; no added-token match crosses it and the encoder drops it before the pre-tokenizer, so a file holding `<｜User｜>`, a web page with a DSML call or a script with `</think>` reads as its characters' own tokens. The template's markup and an image's placeholder (added after) are untouched; a request without such spellings is not copied and encodes byte for byte as before; raw completion prompts keep their special tokens. **By Coinupbtc** |
| `0029-anthropic-budget-default.patch` | none (always on) | **on** | the Anthropic frontend's translation accepts `thinking: {"type": "enabled"}` with no `budget_tokens`: the request then gets the server's `--thinking-budget` default, as an OpenAI-format request without `thinking_budget` already does. Stock refuses such a request outright (`thinking.budget_tokens must be positive and less than max_tokens`), an asymmetry between the two frontends of one engine; still the case at the `deepseek-v41-zig` tip of 2026-10-23. `budget_tokens` present is checked and passed on exactly as before (an invalid one is still refused). **By Maciej Kowalik ([koniaik](https://github.com/koniaik))**, [pull request #53](https://github.com/MiaAI-Lab/DeepSeek-v4.1-Flash-1017-2x-DGX-Sparks/pull/53) |
| `0030-anthropic-context-management-lenient.patch` | none (always on) | **on** | the Anthropic frontend accepts any `clear_thinking_*` context edit with any `keep`: a client that clears the earlier thinking when the user sends a message mid-conversation sends `clear_thinking_20250929` with `keep: "none"` (the cloud accepts both dates and both keeps) and every such request was refused (`context_management supports clear_thinking with keep: all only`), a 400 that ended the turn; other edits are refused as before. **By Maciej Kowalik ([koniaik](https://github.com/koniaik))** |
| `0031-anthropic-system-anywhere.patch` | none (always on) | **on** | the Anthropic frontend accepts a system turn anywhere in messages: it was refused unless it directly followed a user or system turn and directly preceded an assistant turn or the end, and a client that injects a system reminder before the newest user turn — the cloud accepts that — failed every mid-conversation message with 400 invalid_request; the message translates as a system-role chat message, which the chat side takes anywhere. Turn-scoped `clear_at` and per-message `output_config` are still refused. **By Maciej Kowalik ([koniaik](https://github.com/koniaik))** |

With every switch unset, for requests without a `tool_choice` and for prompts shorter than 131,072 tokens, the engine behaves like the pinned one (the indexer split above that keeps the bits: a 399,516-token prompt's greedy reply has the same token hash) (`tools/exact.py` compares token hashes; bit-identity verified for 0001 and 0002 on the earlier pin; 0004 is checked by the same replay; the image of the current pin was not run on a pair). The mixed-pack loader is automatic: a rank cache without plain entries (every EXL3-only pack) takes the old path. Remove a patch from
this folder to leave it out of the image; never run `scripts/prepare.sh` to rebuild with a partial cache.

**The port of Robert Wojciechowski's ([wojo](https://github.com/wojo) on GitHub, [@rwojo](https://x.com/rwojo) on X) GLM patches** (spill v2, continuation, KV sharding with prompt
borrowing and the ring exchange, parked pages) arrives here as `0011` to `0022`, after the hand-written patches above: one patch per
feature, in the order they build on each other, each with a header that says what it does, its switches and defaults, what was
measured on the pair and whose work it is, as the GLM recipe's patches do. They are the commits of the engine branch
`port/series-pair-370daf0` (local to the port's engine repository) over `baseline-370daf0` (TF_REF plus the patches above, `0008`
and `0010` included), without the port's own notes (`PORT.md`, `docs/port/`); the branch's last commit is `0023`, a fix to the base engine that is not the port's (rank 0's memory with long prompts; also
offered alone as its own pull request, with the same bytes as this fork's other copy, so whichever lands first the other is
dropped as a duplicate). Each passes
`git apply --check` on a clean `TF_REF` checkout after the ones before it and gives that commit's tree. Remove them from the last one
back, never one in the middle (each builds on those before it). KV sharding builds on `0008`'s pool: one `POOL`, cut into one part a
Spark when `KV_SHARD=1`. Every switch of these patches is off by default, in the engine and in the recipe (`SPILL_GIB=0`,
`KV_SHARD=0`, `POOL` empty: the recipe as before the port), but for `0020`'s broken-pair exit, which acts only after a
failure; set them in `scripts/local.sh` to turn them on. The recipe's settings for
them are in `scripts/port.sh`, and [docs/PORT-RECIPE.md](../../docs/PORT-RECIPE.md) has their mapping, deployment and rollback.
Engine work after the series is exported on top by `scripts/port-patches.sh --base port/series-pair-370daf0` as `0024-...` and later,
never by hand: it refuses unless the patches here reproduce its base and every new patch applies on a clean `TF_REF` and reproduces
the branch, and it rewrites only the table rows it owns (marked `<!-- port-patches -->`). `scripts/port-patches.sh --dry-run` checks
without writing.

`0003-c1-cache-placement.patch` (`TF_DS_CACHE_PLACEMENT=1`: a resumed prompt moves its kept rows to a free extent instead of over another
conversation's) is gone: the pin moved to `629c524`, whose `lanes.zig` does this itself (`placeSoft` leaves each kept extent room to grow, a
conversation that shares a prefix copies the shared rows to a free extent, `9f82099`/`629c524`), and the patch no longer applies to it. A
`TF_DS_CACHE_PLACEMENT` in your `scripts/local.sh` is ignored now.
